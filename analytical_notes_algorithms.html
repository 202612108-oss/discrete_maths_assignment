Algorithms: Meaning, Properties & Role

Algorithm: A finite, well-defined sequence of effective instructions that accepts input, processes it, and produces output to solve a specified problem. An algorithm describes the method; a program is its implementation in a programming language.

Why algorithms matter

Algorithms provide systematic solutions, enable automation, and allow us to compare alternative methods independently of a particular machine or programming language. A good solution should be correct, clear, efficient, and appropriate for the problem's constraints.

Core characteristics

  • Input: zero or more clearly specified values.
  • Output: at least one result related to the input.
  • Definiteness: every step is precise and unambiguous.
  • Finiteness: execution terminates after a finite number of steps.
  • Effectiveness: each operation is basic enough to be carried out.
  • Generality: solves every valid instance in the intended problem class.

Example: Find the largest of three numbers

Input: a, b, c
largest ← a
if b > largest, largest ← b
if c > largest, largest ← c
output largest

For (8, 13, 5), the result is 13. The method performs a fixed number of comparisons, so its running time is Θ(1) with respect to input size.

Correctness

An algorithm is correct if it produces the required output for every valid input and terminates. A useful proof technique is a loop invariant: state a property that is true before the loop, remains true after every iteration, and implies the desired result when the loop ends.

Remember: Correctness asks “does it solve the problem?” Complexity asks “how much time and memory does it use?”

Types & Design Approaches

Common ways to classify algorithms

By purpose

  • Searching: locate an item (linear search, binary search).
  • Sorting: arrange data (insertion sort, merge sort).
  • Graph: traverse or find paths (BFS, DFS).
  • Numerical: compute mathematical results.
  • String: process text and patterns.

By design technique

  • Brute force: directly examine possibilities.
  • Divide and conquer: split, solve, combine.
  • Greedy: make a locally best feasible choice.
  • Dynamic programming: reuse solutions to overlapping subproblems.
  • Backtracking: build candidates and abandon invalid partial solutions.
  • Randomized: use random choices during execution.

Important design paradigms

1. Brute force

Try a direct, exhaustive method. It is often simple and reliable, but may be expensive. Example: checking every array element for a target gives linear search, Θ(n).

2. Divide and conquer

Divide the input into smaller subproblems, solve them recursively, then combine results. Example: merge sort splits an array, sorts each half, and merges the halves. Its recurrence is T(n)=2T(n/2)+Θ(n), giving Θ(n log n).

3. Greedy method

At each step choose the best immediate option according to a rule. It works only when the problem has the required greedy-choice and optimal-substructure properties. Example: Kruskal's algorithm builds a minimum spanning tree by repeatedly selecting a light edge that does not create a cycle.

4. Dynamic programming

Break a problem into overlapping subproblems and store their results using memoization (top-down) or tabulation (bottom-up). Example: Fibonacci values can be computed in Θ(n) time by storing earlier values rather than recomputing them.

5. Backtracking and randomized methods

Backtracking explores a search tree and prunes partial candidates that cannot lead to a valid solution. Randomized algorithms make random choices; analyze expected running time or probability of error as appropriate.

Choosing a method: Consider input size, constraints, correctness proof, time, memory, and whether an exact or approximate answer is acceptable.

Algorithm Analysis & Complexity

What is complexity?

Complexity estimates the resources required as input size grows. Time complexity counts the growth of elementary operations; space complexity measures memory requirements. Analysis focuses on growth rather than seconds on one particular computer.

Input size and operation counting

Let n represent input size. Identify the basic operation, count how often it executes, and express the count as a function T(n). Ignore machine-specific constants when studying asymptotic growth.

Example: for i = 1 to n, perform one constant-time operation.
T(n)=c·n+d, therefore T(n)=Θ(n).

Best, average, and worst cases

  • Best case: minimum work for an input of size n.
  • Worst case: maximum work for an input of size n.
  • Average case: expected work under an assumed input distribution.

Linear search is best-case Θ(1) when the first item matches, worst-case Θ(n) when the item is last or absent, and has expected Θ(n) comparisons under a common uniform-position model.

Common growth rates

  1. Θ(1) — constant
  2. Θ(log n) — logarithmic
  3. Θ(n) — linear
  4. Θ(n log n) — linearithmic
  5. Θ(n²), Θ(n³) — polynomial
  6. Θ(2ⁿ) — exponential
  7. Θ(n!) — factorial
Typical order from slower to faster growth: 1 < log n < n < n log n < n² < n³ < 2ⁿ < n! .

Why growth matters

For large inputs, an algorithm with lower asymptotic growth usually scales better. However, constants, memory use, input structure, and implementation details can matter for small or practical workloads.

Growth of a Function

Growth of a function describes how quickly a mathematical function increases as n becomes large. In algorithm analysis, functions represent operation counts or memory use.

Asymptotic notations

Big-O: asymptotic upper bound

f(n)=O(g(n)) if there are constants c>0 and n₀ such that 0≤f(n)≤c·g(n) for all n≥n₀.

It says f does not grow faster than a constant multiple of g beyond some point.

Big-Omega: asymptotic lower bound

f(n)=Ω(g(n)) if there are constants c>0 and n₀ such that 0≤c·g(n)≤f(n) for all n≥n₀.

It gives a lower growth bound.

Big-Theta: tight asymptotic bound

f(n)=Θ(g(n)) if f(n)=O(g(n)) and f(n)=Ω(g(n)).

It means f and g grow at the same asymptotic rate, up to constant factors.

Worked examples

f(n)=3n²+5n+7

For large n, the n² term dominates. Constant factors and lower-order terms do not affect the asymptotic class. Therefore f(n)=Θ(n²), and consequently f(n)=O(n²) and Ω(n²).

g(n)=7n log n+4n

The n log n term dominates n, so g(n)=Θ(n log n).

Little-o and little-omega

f(n)=o(g(n)) means f grows strictly slower than g; equivalently, f(n)/g(n)→0. f(n)=ω(g(n)) means f grows strictly faster; the ratio tends to infinity.

Important: Big-O is not automatically the tight bound. If T(n)=Θ(n), it is also O(n²), but O(n) is more informative.

Analyzing Loops & Recurrences

Loop patterns

Single loop

for i=1 to n
constant work

Runs n times: Θ(n).

Nested loops

for i=1 to n
for j=1 to n
constant work

n×n operations: Θ(n²).

Halving loop

while n>1
n=n/2

Number of halvings is about log₂n: Θ(log n).

Triangular loop

for i=1 to n
for j=1 to i
constant work

1+2+…+n=n(n+1)/2: Θ(n²).

Recurrence relations

Recursive algorithms are often described by recurrences. A recurrence expresses the running time on size n in terms of smaller input sizes plus the work done outside recursive calls.

Example: binary search

T(n)=T(n/2)+Θ(1)

Each call halves the search interval and performs constant extra work. The number of levels is Θ(log n), so T(n)=Θ(log n).

Example: merge sort

T(n)=2T(n/2)+Θ(n)

There are two half-size recursive calls and Θ(n) work to merge. The recursion tree has Θ(log n) levels and Θ(n) work per level, so T(n)=Θ(n log n).

Master theorem (common form)

For T(n)=aT(n/b)+f(n), where a≥1 and b>1, compare f(n) with n^(log_b a).

  • If f(n)=O(n^(log_b a−ε)) for some ε>0, then T(n)=Θ(n^(log_b a)).
  • If f(n)=Θ(n^(log_b a) log^k n), then T(n)=Θ(n^(log_b a) log^(k+1)n).
  • If f(n)=Ω(n^(log_b a+ε)) and the regularity condition holds, then T(n)=Θ(f(n)).

Space Complexity, Comparison & Quick Revision

Space complexity

Space complexity measures memory usage as a function of input size. It can include input storage, auxiliary data structures, temporary variables, and recursion stack space. Auxiliary space usually refers to extra space used by the algorithm, excluding the input itself.

  • Iterative sum of an array: Θ(1) auxiliary space.
  • Copying an array of n elements: Θ(n) extra space.
  • Recursive calls may use stack space proportional to recursion depth.

Time-space trade-off

Some algorithms use extra memory to reduce running time. Hash tables, memoization, and lookup tables are common examples. A good choice balances speed, memory limits, simplicity, and correctness.

Exam checklist

  • Define the input size and basic operation.
  • Count loop iterations or form a recurrence.
  • State whether the result is best, average, or worst case.
  • Use O, Ω, and Θ correctly; prefer a tight Θ bound when known.
  • Include auxiliary space and recursion stack when relevant.
  • Explain assumptions and justify the final bound.
Final takeaway: Algorithm analysis connects a problem-solving method to measurable resource growth. Correctness, time complexity, and space complexity together describe the quality and scalability of an algorithm.
